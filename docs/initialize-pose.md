# 独立站姿初始化

这是一个独立动作：**使能 12 个舵机，从当前实测位置缓慢移动到
`config/poses/standing.json`，确认到位后结束。** 不运行策略，不要求匹配低趴记录，
不修改舵机零点、ID、模型角度标定或位置文件，也不依赖 IMU。

目标按 ID 1–12 为 `[468,280,382,535,724,607,500,193,357,499,803,663]`。
单位是位置记录中的舵机计数。上位机负责插值，STM32 发出 LOAD=1 与 MOVE_TIME_WRITE。
上电本身不会触发这个动作。

## 使用

先烧录配套 `../dog/MDK-ARM/dog/dog.hex`（2026-10-20 pose-v1 版本），再使用
香橙派桌面“Robot12 策略启动”菜单 **8：初始化到已记录站姿**。这项操作不会运行 ONNX。
与策略控制使用同一个桌面文件锁；急停图标对初始化进程同样有效。

等价终端命令：

```bash
cd /home/orangepi/dog-3588
.venv/bin/python -m dog3588 --config config/local-model4497.yaml initialize-pose --arm --seconds 5 --log logs/initialize-pose.jsonl
```

去掉 `--arm` 只检查固件能力和 12 轴位置反馈，不使能、不发送运动位置。
旧固件会明确返回“不支持 pose-v1”，程序不再尝试使能或发位置。
串口仍为 UART1 `/dev/ttyS1`、921600，`standing_pose` 路径取自本地配置。

先以当前位置保持约 0.5 秒，再使用五次曲线移动；默认最少 5 秒，最大速度
40 count/s，根据实际距离自动延长。每 40 ms 下发一次短时位置命令。
到目标每轴误差不超过 5 count，连续保持 0.5 秒才报告到位；超时或失联退出。
这只确认编码器位置到位，不代表通过 IMU 验证了机身平衡。

完成或异常退出均发送 STOP、结束会话。STOP 清除尚未发出的动作，已发出的短动作最多
继续其剩余 40 ms；不发送卸载命令，到位后舵机保留力矩。若关机断电，力矩不会保留。

## 配套固件协议（pose-v1）

沿用 RobotLink v1 帧、CRC、序号和 STM32 tick 回显。普通策略 ARM/TARGET 保持弧度语义。

| 类型 | payload | 作用 |
|---|---|---|
| `0x05 POSE_CAPS` | 空 | 无运动的能力查询；匹配 ACK=OK 才能继续 |
| `0x06 POSE_ARM` | `mask:u16=0x0fff` | 选择初始化会话，要求新鲜心跳及全部 12 轴原始反馈 |
| `0x07 POSE_TARGET` | `mask:u16,duration_ms:u16,position:u16[12]` | 全部位置验证成功后排队执行；首帧每轴 LOAD=1 在 MOVE 之前 |

两种会话的目标帧禁止混用。初始化反馈有效性不要求模型角度已标定；固件使用既有
`g_joint_servo_config` 的 ID/总线映射，不猜测模型方向或比例。
检查范围 0–1000 count、单帧增量 ≤10 count、目标与实测误差 ≤40 count、动作时间
1–100 ms；主机额外将跟随误差限制为 35 count。沿用 100 ms 目标超时、300 ms 心跳超时、
100 ms 帧时效、失效反馈停机及 STOP。0–1000 是舵机编码范围，不代表所有机构姿态都可达；
该动作面向用户已记录的站姿，路径的实物稳定性仍需首次测试。
