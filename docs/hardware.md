# 接线与标定

## 已确认与尚未确认

2026-10-16 SSH 实测：板型 `RK3588 OPi 5 Max`，Ubuntu 22.04.5，内核 `6.1.99-rockchip-rk3588`，约 8 GB 内存。只有 `/dev/ttyS7`；没有 `/dev/ttyS1/3/4/6`、USB 串口和可采集的 `/dev/video0`。`/dev/video-dec0`、`video-enc0` 不是摄像头。

用户现有 `project/dog` 工程已打通左前腿 ID 1、2、3，USART2=115200/8N1。四路分配是本项目的部署规划；旧 STM32 工程实际只有左右两条总线。本项目未修改其接线或固件。

| 腿 | 本项目总线名 | 舵机 ID | 串口规划占位 |
|---|---|---|---|
| 左前 LF/FL | fl | 1、2、3 | `/dev/ttyS1` |
| 右前 RF/FR | fr | 4、5、6 | `/dev/ttyS3` |
| 左后 LH/RL | rl | 7、8、9 | `/dev/ttyS4` |
| 右后 RH/RR | rr | 10、11、12 | `/dev/ttyS6` |

串口名字不等于物理排针号。2026-10-17 已按项目根目录 **Orange Pi 5 Max 用户手册 v1.4** 第 16、211–212、219、221 页核对，并与板端设备树交叉检查；实际 40 针复用总表、四路 UART 和 I2C 冲突见 [README 硬件引脚配置](../README.md#硬件引脚与接口配置)。UART1_M1 的 TX/RX 为 28/27，UART3_M1 为 31/33，UART4_M2 为 23/19，UART6_M1 为 13/11；I2C IMU 推荐 I2C2_M0 的 SDA=3、SCL=5，本地配置应填写 `i2c_bus: 2`。这些是物理脚号，不是 GPIO offset。按最新接线方案，四路均不需要方向使能 GPIO。

板端对应 overlay 已存在，但当前四 UART 未启用，也未做接线验收。按 README 的互斥约束选择 `uart1-m1`、`uart3-m1`、`uart4-m2`、`uart6-m1` 和可选 `i2c2-m0`，再用 `orangepi-config` 启用；保存原 boot 配置并在维护窗口重启。不要占用调试口或把多个互斥复用同时打开。

本次未修改 `/boot/orangepiEnv.txt`，未启用串口 overlay，未重启。根据接线选择相应配置后，再填写设备路径。USB 自动半双工串口方案可先绕过排针复用调试，使用稳定的 `/dev/serial/by-id/...` 名称。

## LX824 不是普通四线全双工设备

舵机侧只有 DATA 信号。当前方案每条腿使用一块自动方向转接电路，主机侧接 **TX、RX、GND**，不接 TX_EN/RX_EN；转接器供电按模块规格独立核对。收发切换由转接电路完成，不由香橙派 GPIO 完成。

每条腿需要一条真正独立的 DATA 总线。若当前物理板把左右各六个舵机并在同一数据线上，只改软件的端口数量不会变成四路，需要把四腿信号线分别引出。

### 自动方向转接器

默认四路 `direction.mode: auto`，不需要 `chip`、`tx_enable`、`rx_enable` 字段，也不需要 GPIO 权限或 gpiod 依赖。旧本地配置若仍使用 `gpio` 模式，需同步改为 `auto` 并删除旧方向引脚字段；库中的 GPIO 驱动仅保留供旧硬件兼容，不属于当前默认接线方案。

确认转接电路能在最后停止位后自主释放 DATA，且兼容 3.3 V UART 电平。该模式绝不代表可以把香橙派 TX/RX 裸线直接短接到舵机 DATA，也不能把必须外控的旧转接板使能脚悬空后当成自动方向板。一般 RS485 差分收发器与这里的单线 TTL 不是同一种接口。

发送仍使用 `flush()` / Linux `tcdrain` 等待发送排空；应通过逻辑分析仪和连续查询检查应答首字节、回读丢包率与超时。USB 转接器也要实测收发延迟，普通 USB-TTL 模块不等于自动半双工舵机适配器。

### 电源

普通 LX824 厂商规格为 6–8.4 V，不要与 LX824HV 的电压混用。舵机必须用满足电流需求的独立供电，与香橙派/转接板共地；不能由香橙派 3.3 V/5 V 排针给十二个舵机供电。香橙派信号脚不接舵机电源电压。保留物理电源急停、初次运动时用支架托住机器人。

依据：[Hiwonder LX824 产品规格](https://www.hiwonder.com/products/lx-824)。协议实现以用户已有 `Drivers/Servo/Src/lx824.c` 和 `Docs/servo_feedback.md` 的 115200 总线协议为准，不能替换成幻尔“舵机控制板”的 9600 波特率上位机协议。

## 调试顺序

1. 填好 `config/local.yaml` 的一个真实串口并设置 `direction.mode: auto`，接入自动方向转接电路及已经确认的 ID 1/2/3，运行 `probe-servos --bus fl --rounds 100`。该命令仅查询位置，不发 LOAD/MOVE。
2. 观察 ID、原始计数、往返耗时；人工缓慢转动已卸载且安全支撑的关节，确认回读变化。断开一个舵机，确认只有该 ID 超时，其他 ID 可继续查询。
3. 分别验证四路，每路三 ID。`query_period_s=0.006` 指同路相邻查询最小起点间隔，正常每关节约 18 ms 一次，取决于真实应答。配置默认的 8 ms 应答超时和超时后 6 ms 静默需用实测修正。
4. 每个电机填 `raw_zero`、`direction`、`zero_rad`、安全机械 `min_rad/max_rad`，确认不是被动关节角度。用两点标定检查正负与比例，且两端换算必须在 0–1000 内；完成后该项 `verified: true`。
5. 选定 IMU，配置安装变换与校准，运行 `probe-imu`。静止时角速度接近零、重力模长约 1、平放 z 约 -1。前后/左右倾斜检查符号，再设 `mount_verified: true`。
6. 完成四路稳定回读后，各总线 `verified: true`；运行实物只读推理，检查目标是否连续且在限位内。记录传感器年龄和控制延迟。
7. 托住机身，人工放到训练初始姿态附近（默认最大误差 0.25 rad），再显式使用 `--hardware --arm`。启动不是自动站起动作。默认速度为零，先验证站立；低速短时命令逐步测试。

## IMU 选型接口

- `wit_serial`：支持厂家标准 `0x55 0x52` 角速度和 `0x55 0x53` 欧拉角数据，11 字节含和校验。需让设备持续输出这两项、波特率匹配。未收到两项完整数据时状态无效。没有自动写设备波特率/标定参数。
- `mpu6050_i2c`：检查 `WHO_AM_I=0x68`，配置 ±4g、±2000°/s、44 Hz DLPF、200 Hz 采样；软件互补滤波估计重力。需静止启动、测量陀螺零偏。没有可靠航向或机体线速度估计，剧烈平移加速度仍会影响姿态，正式行走宜选带成熟姿态融合的 IMU。
- 四路硬 UART 都给舵机时，可让 IMU 走 I2C，或给串口 IMU 独立 USB 串口，不要与 LX824 同线混接。
- 已存在多个 `/dev/i2c-*` 不代表都接到排针；不要盲扫所有总线，它们可能连着板载器件。普通用户当前有 dialout/video 权限；I2C/GPIO 权限按实际设备组/udev 配置。

参考：[WIT 标准协议](https://wit-motion.gitbook.io/witmotion-sdk/wit-standard-protocol/wit-standard-communication-protocol)、[TDK MPU6050 寄存器文档](https://invensense.tdk.com/wp-content/uploads/2015/02/MPU-6000-Register-Map1.pdf)。

## 摄像头

最快的初期路径是系统可枚举的 UVC USB 摄像头，先用 640×480/30 FPS。MIPI 型号依赖香橙派内核、设备树、ISP 和对应传感器驱动，不能假设插上就能读；先让系统产生可用的视频采集设备，再接本框架。

检测使用 BGR 图像与 HSV 阈值，默认下半部分寻找黑线。地面照明、镜头畸变、视角和线宽改变后需要重新调阈值/ROI。图像右侧的线默认产生负偏航（右转），镜像或旋转安装必须验证。置信度用于诊断，未加入交叉线决策、路口导航或颜色任务状态机。
