# 接线、接口顺序与标定

初始姿态、模型关节零位与舵机原始计数的标定关系见 [初始姿态对照图与尺寸](initial-pose.md)。

## 当前架构与适用范围

本表对应 Orange Pi 5 Max（RK3588）与 STM32 的分工：**ToF、USB 相机直接接香橙派，四腿舵机接 STM32**。2026-10-18 核对相邻 `project/dog` 工程时，其最新版本还已将 CH040 IMU 迁到香橙派，STM32 只保留舵机和主机通信。

本页为接线分配与软件状态记录。香橙派 UART1 用于 STM32，用户已确认接线且已完成舵机读数和指定姿态动作；UART3 已收到 CH040 数据。旧 `config/robot.yaml` 的四腿直连方式仅作为历史调试方案保留。

**2026-10-20 软件状态：** `config/model4497.yaml` / `robot-deploy.yaml` 已改用 `hipnuc_serial`，支持香橙派直连 CH040 的 HI83/HI91 混合流。策略与桥接看门狗检查同一主机 IMU 状态，不再等待 MCU IMU 遥测。实机 `local-model4497.yaml` 的主机链路使用 **921600 8N1**；模板链路仍需按实机填写。ToF 的 VL53L8 Linux 驱动尚待移植，现有 `vl53l5cx_ctypes` 不能作为 L8 驱动使用。

## 1. 整机接口对应表

TX/RX 均从该列所属设备的视角命名；UART 必须 TX 接对端 RX，I²C 必须 SDA 接 SDA、SCL 接 SCL。

| 顺序 | 硬件 | 香橙派接口与物理脚号 | 对端接口 | Linux 设备 / 配置 | 状态 |
|---:|---|---|---|---|---|
| 1 | STM32 主机链路 | UART1_M1：TX **28**、RX **27**、GND **30** | USART6：RX **PG9**、TX **PG14**、GND | `/dev/ttyS1`；`bridge.port`，921600 8N1 | 已联调读数与姿态动作 |
| 2 | CH040 IMU | UART3_M1：RX **33**、TX **31**、GND **34** | 模块 TXD1 **11** → 主机 RX；模块 RXD1 **12** ← 主机 TX；模块 GND **2/8** | `/dev/ttyS3`；HI83/HI91，**460800 8N1、合计约 100 Hz** | 已收到有效数据，主机驱动已实现 |
| 3 | ToF | I2C2_M0：SDA **3**、SCL **5**、GND **6** | 模块 SDA、SCL/SCK、GND | `/dev/i2c-2`；`tof.i2c_bus: 2`，7 位地址 `0x29` | overlay 已写入；L8 与现有 L5 驱动不同 |
| 4 | USB 相机 | 板载 USB Host 接口，不占 40 针 | UVC 摄像头 USB 插头 | `/dev/v4l/by-id/...`，或实测对应的 `/dev/videoN`；`vision.source` | 待插入并确认采集节点 |
| 5 | 四腿舵机 | 不接香橙派 UART | STM32 四路 UART → 自动方向转接电路 → 各腿 DATA | 见第 5 节 | 不在主机 `buses` 中配置四腿串口 |

香橙派 UART1 与 STM32 USART6 **不要求编号相同**，它们是两颗芯片各自的外设编号。CH040 表中的 11/12/2/8 是**模块本体脚号**，不是香橙派脚号；使用转接板时按转接板标识核对。

2026-10-20 11:38 实测 460800 下 5 秒收到 499 个 CRC 正确帧：HI83 100 帧、HI91 399 帧，合计约 99.8 Hz，不能将两种帧各自称为 100 Hz。用户确认安装为 X 朝前、Y 朝左、Z 垂直，按右手坐标系为 Z 朝上，主机使用单位旋转矩阵。HI91 角速度由 deg/s 转为 rad/s，HI83 角速度已为 rad/s；四元数计算机体系重力。驱动检查 CRC、数据完整性、收敛/饱和状态、时间戳和新鲜度，不向模块写配置。STM32 主机链路独立使用 921600，四腿总线为 115200。

也可用独立 USB-TTL 连接 STM32：USB-TTL TX → PG9，RX ← PG14，GND 共地，填写稳定的 `/dev/serial/by-id/...`。USB-TTL 方案与上述 UART1 是二选一，不把两个主机 TX 同时接到 PG9。接口必须兼容 3.3 V 逻辑，不接 RS232 电平。

## 2. 香橙派 40 针排列顺序

先找板上的 **Pin 1 标记**。下表只表示针脚编号的两列关系，不代表任何旋转照片中的左右方向。每行是一对相邻针脚；从 1/2 向 39/40 顺序排列。这里列出本项目用途，完整芯片复用表见 [README 引脚总表](../README.md#40-针物理脚号与复用功能总表)。

| 奇数脚 | 本项目用途 | 偶数脚 | 本项目用途 |
|---:|---|---:|---|
| 1 | 3.3 V 电源；模块适配电压确认后使用 | 2 | 5 V 电源；不是逻辑信号 |
| 3 | **ToF SDA，I2C2_M0** | 4 | 5 V 电源；不是逻辑信号 |
| 5 | **ToF SCL，I2C2_M0** | 6 | **ToF GND** |
| 7 | 未分配 | 8 | 调试 UART TX，保留 |
| 9 | GND，可选共地点 | 10 | 调试 UART RX，保留 |
| 11 | UART6 RX，当前未分配 | 12 | 未分配 |
| 13 | UART6 TX，当前未分配 | 14 | GND，可选共地点 |
| 15 | 未分配 | 16 | 未分配 |
| 17 | 3.3 V 电源；模块适配电压确认后使用 | 18 | 未分配 |
| 19 | UART4 RX，当前未分配 | 20 | GND，可选共地点 |
| 21 | 未分配 | 22 | 未分配 |
| 23 | UART4 TX，当前未分配 | 24 | 未分配 |
| 25 | GND，可选共地点 | 26 | 未分配 |
| 27 | **UART1 RX ← STM32 PG14 TX** | 28 | **UART1 TX → STM32 PG9 RX** |
| 29 | 未分配 | 30 | **STM32 GND** |
| 31 | **UART3 TX → CH040 RXD1（模块 12 脚，命令预留）** | 32 | 未分配 |
| 33 | **UART3 RX ← CH040 TXD1（模块 11 脚）** | 34 | **CH040 GND** |
| 35 | 未分配 | 36 | 未分配 |
| 37 | 未分配 | 38 | 未分配 |
| 39 | GND，可选共地点 | 40 | 未分配 |

“未分配”不等于可随意上电或可同时使用所有复用功能。物理脚号、GPIO bank/offset 和 `/dev/ttyS*` 是不同编号体系，不可混填。排针依据仓库内 Orange Pi 5 Max 用户手册 v1.4 及 README 已核对的设备树记录。

## 3. ToF 模块接口逐线对应

数据路径为：**ToF → 香橙派 I²C → 上位机处理**；没有 STM32 转发环节。断电后将原 STM32 PB6/PB7/PB8 连接移除，再按实际模块接口接线。

| 模块端标识 | 接到香橙派/电路的位置 | 说明 |
|---|---|---|
| SDA | 物理 **3** 脚，GPIO0_C0 | 双向数据；上拉与逻辑电平需匹配 |
| SCL / SCK | 物理 **5** 脚，GPIO0_B7 | I²C 时钟；不要误接 SPI MOSI |
| GND | 物理 **6** 脚 | 共地 |
| UIN / VIN / VCC | 按所用模块规格接电源 | 下位机资料记录的 L8 模块 UIN 支持 3.3/5 V，但仍须核对实物；不能用于推断裸芯片供电 |
| SPI_I2C_N（若有） | 模块 GND | 下位机记录的 L8 模块选择 I²C 模式 |
| LPn（若有） | 按模块要求保持通信使能电平 | 当前主机驱动不控制 LPn；不再连接 STM32 PB8，不直接假设可上拉至 3.3 V |
| MISO / INT（若有） | 当前轮询方案不连接 | 不作为 SDA 或 SCL |
| NCS（若有） | 按模块电路的 I²C 模式偏置 | 现有 L8 资料对模块悬空与裸芯片下拉有差异，确认板内偏置后接线 |

模块排针的物理排列、线色和 LPn 电平不能由这张逻辑接线表推断。裸 VL53L8 的数字接口不等同于香橙派 3.3 V 逻辑；模块有 LDO 也不证明 SDA/SCL/LPn 已做电平转换，需检查转接板原理图。

当前代码只实现 VL53L5CX 驱动。如果实物是下位机资料记录的 **VL53L8**，需先适配其驱动，不能认为同为 64 区、同为 `0x29` 就可互换。此前桌面菜单 **7** 调用的是现有 L5 驱动，仅在型号匹配时使用。高度阵列顺序、安装方向与 8 个训练采样点需另行标定，详见 [ToF 文档](tof.md)。

## 4. USB 相机与电源

USB 相机直接插入香橙派 USB Host 接口，不经过 STM32，也不占 SDA/SCL 或 UART 针脚。使用 `v4l2-ctl --list-devices` 确认实际采集节点；`/dev/video-dec0`、`video-enc0` 是编解码设备，不是相机。插口位置不保证 `/dev/video0` 编号固定，优先使用实际存在的 `/dev/v4l/by-id/...`。

部署默认 640×480、30 FPS，`robot-deploy.yaml` / `model4497.yaml` 使用白色赛道阈值；旧 `robot.yaml` 使用黑线阈值。安装后需核对镜像、图像方向、ROI 和颜色范围。当前已有颜色检测及任务状态机，但现场几何事件仍需实现/标定，见 [任务说明](mission.md)。

香橙派使用符合板卡要求的独立电源；舵机使用满足电压和负载电流要求的独立电源，与控制板/转接器共地。十二个舵机不能由香橙派 3.3 V/5 V 排针供电，舵机大电流回路不要经过细信号地线。模块供电和信号电平分开核对。

## 5. STM32 四腿接口与关节顺序

以下来自当前 `../dog/Docs/hardware_uart_mapping.md`、`Core/Src/stm32f4xx_hal_msp.c` 与 `Robot/Src/robot_config.c`。MCU 端 TX/RX 均从 STM32 视角命名；STM32 开发板连接器上的排针序号尚未提供，按 **PA2、PG9 等丝印/原理图**定位，不把 MCU 引脚名当作开发板连接器脚号。

| 顺序 / 策略索引（从 0 开始） | 腿 / 总线名 | 舵机 ID 顺序 | STM32 外设 | MCU TX | MCU RX | 参数 |
|---|---|---|---|---|---|---|
| 1 / 0、1、2 | 左前 FL（LF）/ `fl` | 1、2、3 | USART2 | **PA2** | **PA3** | 115200 8N1 |
| 2 / 3、4、5 | 右前 FR（RF）/ `fr` | 4、5、6 | USART3 | **PB10** | **PB11** | 115200 8N1 |
| 3 / 6、7、8 | 左后 RL（LH）/ `rl` | 7、8、9 | UART4 | **PC10** | **PC11** | 115200 8N1 |
| 4 / 9、10、11 | 右后 RR（RH）/ `rr` | 10、11、12 | UART5 | **PC12** | **PD2** | 115200 8N1 |
| 独立主机链路 | 香橙派 | 不连接舵机 DATA | USART6 | **PG14** | **PG9** | 最新源码 921600 8N1 |

每腿三关节依次为 **hip（髋侧摆）→ upper（上部驱动）→ input（连杆输入驱动）**；完整策略数组顺序为：

```text
fl_hip, fl_upper, fl_input,
fr_hip, fr_upper, fr_input,
rl_hip, rl_upper, rl_input,
rr_hip, rr_upper, rr_input
```

对应完整名称以策略 manifest 的 `joint_names`（`*_joint`）为准。下位机部分枚举命名为 KNEE，部署对应的是受驱动的 input 关节，不能据名称直接换成被动膝关节角度。ID 顺序不代表线缆插头左右顺序；串联 DATA 总线以 ID 区分舵机。

每腿使用独立的自动方向转接电路：MCU TX → 转接器发送输入，MCU RX ← 转接器接收输出，GND 共地，再将转接器 DATA 接该腿三个 LX824。当前不分配 TX_EN/RX_EN；不能把 MCU TX/RX 裸线短接到 DATA，也不能用普通 RS485 差分收发器替代单线 TTL 适配器。每腿必须是独立 DATA 总线。

## 6. 板端状态、配置与接线验收顺序

2026-10-18 在 `192.168.0.102` 的最近一次检查：

- 已有 `/dev/ttyS1`、`ttyS3`、`ttyS4`、`ttyS6`、`ttyS7`；UART1/3/4/6 overlay 已启用。`ttyS7` 不在本表中分配。
- 未发现 USB 串口或相机采集节点，未验证实际线缆。
- 已在 `/boot/orangepiEnv.txt` 的原 UART 配置后追加 `i2c2-m0`，已有备份；`orangepi` 已加入 `i2c` 组。写入时尚无 `/dev/i2c-2`，本次未执行重启，重启后需重新检查。
- 主机项目位于 `/home/orangepi/dog-3588`；桌面使用 `config/local-model4497.yaml`。当前 280 维策略不直接接收 ToF 高度。

本表分配需要 `uart1-m1`、`uart3-m1`、`i2c2-m0`。不要同时启用与 UART1 冲突的 `i2c5-m3`、与 UART3 冲突的 `can1-m0`。现有 UART6/4 仍启用时，也不要启用冲突的 `i2c2-m4` / `spi4-m2`、`spi0-m2`。没有为本文自动更换 UART 分配、修改部署波特率或关闭其他 overlay。

建议按以下顺序验收：

1. 断电核对模块型号、供电、地线、电平；按第 2 节针脚表连接 ToF、IMU、主机链路，四腿按第 5 节接到 STM32。
2. 启动香橙派，确认 `/dev/ttyS1`、`/dev/ttyS3`、`/dev/i2c-2` 和相机采集节点。只检查所用总线，不盲扫全部板载 I²C。
3. 确认 STM32 实际烧录版本。在本地配置填入 `bridge.port`，对齐双方波特率。新源码是 921600，当前主机模板仍是 115200；本文没有代替硬件测试修改这些值。
4. 先读关节链路，再分别验证匹配型号的 IMU、ToF 和相机驱动。最新版 STM32 已停用 IMU/ToF 遥测；主机 IMU 已迁移，VL53L8 驱动仍待完成。关节零位、方向及用户确认的 LX-824 直连换算比例已记录在 `config/poses/standing-zero.json`；常规部署仍需实测机械限位；本次用户授权的策略试验使用单独的 `model4497-test.yaml`，由香橙派进行全部角度/计数换算，经 pose-v1 下发原始计数，并使用明确的软件测试边界，见 [策略测试状态](policy-test.md)。
5. 按策略顺序核对十二个电机的 ID、方向、零位和机械限位；核对 IMU 安装坐标，ToF 射线/外参及相机方向。完成实测后才填写对应 `verified` 字段。
6. 先运行影子推理，再在支撑条件下做有限时长的 `--hardware --arm` 测试。初始速度为零，启动不等于自动站起；保留物理急停。

## 7. 历史直连方案（仅 `config/robot.yaml`）

旧方案让香橙派直接控制四腿，映射为 FL→UART1（TX28/RX27）、FR→UART3（TX31/RX33）、RL→UART4（TX23/RX19）、RR→UART6（TX13/RX11）。每条腿需要独立自动方向转接器；使用 `buses[].port`、`direction.mode: auto`，通过 `probe-servos` / `feedback-servos` 调试。

此映射与本页当前 UART1→STM32、UART3→CH040 的分配互斥，**不能同时接线运行**。原 `wit_serial` 与 `mpu6050_i2c` 驱动也不等于 CH040 HI91 驱动。旧 README 中四腿串口表描述的是这一历史方案；当前工程接线优先按本页对应架构核对。
